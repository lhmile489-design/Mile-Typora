# 接口契约

> 前端经 `src/lib/transport.ts` 调用的 Go 绑定方法、事件和错误码清单。代码是权威：改了 `internal/service/` 的导出方法、`internal/contract/` 的类型或事件后，运行 `bun run generate`，并同步本文。
> 最后更新：2026-11-16（M3-2）

## 1. 通用约定

- 绑定方法的第一个参数是 `context.Context`，生成的 TypeScript 函数里没有这个参数。Go 用 `mygo.CallerWindow(ctx)` 确定调用窗口，不接受前端传来的窗口 ID 或绝对路径。
- **可预期的失败**放在返回值的 `failure` 字段（`contract.Failure`）。前端的 `CallError` 只有 `message` 和 `method`，带不了错误码（decisions.md D-T01）。
- **意外故障**（程序缺陷、窗口上下文丢失）返回 Go `error`。前端 `transport.ts` 的 `wrap()` 把它转成 `{ ok: false, message }`，界面显示通用错误。
- JSON 字段一律用小驼峰。

### 1.1 Failure

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | string | 错误码，见第 3 节 |
| `detail` | string | 给用户看的一句话，不含正文和未授权路径 |
| `size` | number，可选 | `too_large` 时的实际大小（字节） |
| `limit` | number，可选 | `too_large` 时的上限（字节） |

## 2. 绑定方法

### WindowService.Ready

- **TS**：`WindowService.ready(): Promise<ReadyInfo>`；组件通过 `transport.ready(): Promise<Outcome<ReadyInfo>>` 调用。
- **用途**：页面加载后的就绪握手，确定当前窗口，并把该窗口标记为就绪（之后的打开请求会以事件提示）。请求本身由 `Pending` 取，`Ack` 确认，见下文。
- **返回 `ReadyInfo`**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `windowId` | number | `win.ID()`，只用于显示和日志，前端不能用它定位窗口 |
| `version` | string | 应用版本；开发期可能为空，界面显示为 `dev` |
| `startupNotice` | string，可选 | 本次启动为什么没有恢复上次的内容（例如"上次阅读的内容已不存在，已打开空白页"），页面在状态栏提示 |

- **error**：
  - `no calling window`（`service.ErrNoCallerWindow`）：调用没有来源窗口
  - `calling window is not open`（`service.ErrWindowNotOpen`）：来源窗口不在注册表里，属程序缺陷

### WindowService.Pending

- **TS**：`WindowService.pending(after: number): Promise<PendingResult>`；组件通过 `transport.pending(after)` 调用。
- **用途**：取出 seq 大于 `after`、且页面尚未确认的打开请求，按 seq 升序。
- **返回 `PendingResult`**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `requests` | OpenRequest[] | 未确认的请求；没有时为空数组 |

`OpenRequest`：`seq`（number，窗口内递增，用于去重与排序）、`path`（string，可选，命令行参数或页面请求的路径）。

- **幂等**：未确认的请求会在每次调用时重新返回。页面重挂载或重新加载后重新取一次，不会丢请求（PRD §9.2.3）。

### WindowService.Ack

- **TS**：`WindowService.ack(seq: number): Promise<void>`。
- **用途**：确认 seq 及之前的请求都已被页面处理，从队列中释放。旧的 seq 不会回退。
- **error**：来源窗口无效时同 `Ready`。

### WindowService.OpenRequested

- **TS**：`WindowService.openRequested(seq: number): Promise<LoadResult>`；组件通过 `transport.openRequested(seq)` 调用。
- **用途**：打开某个打开请求指向的文件——文件关联、命令行参数、第二个实例。路径来自操作系统，用户启动应用即授权；仍过真实路径、扩展名、10 MiB、UTF-8 与渲染检查。
- **返回 `OpenRequestResult`**：`kind` 为 `file`（带 `doc`；若文件在窗口当前目录内，另带 `rel`，页面据此保留文件树）或 `folder`（带 `folder.root` / `folder.name`）；`kind` 为空表示请求交给了新开的窗口；`failure` 见错误码。
- **确认**：处理完（无论成功失败）即 `Ack(seq)`。同一 `seq` 再次调用时返回窗口当前内容（文档或文件夹），页面重挂载（React StrictMode）或刷新不会丢。
- **错误码**：请求已处理且窗口没有内容时返回 `request_expired`。

### WindowService.GetSettings

- **TS**：`WindowService.getSettings(): Promise<SettingsResult>`。
- **用途**：读设置与最近列表。应用数据目录不可用时返回 `settings_unavailable`（仍按默认值返回）；配置文件损坏时 `corrupt: true` 并带 `settings_corrupt`，`detail` 说明原文件已保留。
- **返回**：`settings.startup`（`blank` / `resume`）、`settings.appearance`（`system` / `light` / `dark`）、`settings.recent`（最多 20 条，新的在前，含 `path`、`name`、`isDir`）。

### WindowService.SaveSettings

- **TS**：`WindowService.saveSettings(view)`。
- **用途**：写 `startup` 与 `appearance`；最近列表由 Go 维护，页面传入的值被忽略。写入失败返回 `settings_write_failed`（"本次设置未保存"），旧值保持不变。

### WindowService.ClearRecent

- **TS**：`WindowService.clearRecent()`：清空最近列表；失败返回 `settings_write_failed`。

### WindowService.OpenRecent

- **TS**：`WindowService.openRecent(path)`：只接受最近列表里已记录的路径（大小写不敏感比较），否则 `not_found`；文件按单文件打开、文件夹按目录打开，返回 `OpenRequestResult`。

### WindowService.OpenLink

- **TS**：`WindowService.openLink(href: string): Promise<LinkTarget>`；组件通过 `transport.openLink(href)` 调用。
- **用途**：文档里点到链接时由 Go 判断该做什么（PRD FR-06）。页面永远不自己导航：所有点击都 `preventDefault`。
- **返回 `LinkTarget.kind`**：
  - `anchor`：带 `anchor`（去掉 `#` 的片段），页面滚动到该元素；
  - `document`：带 `rel`（相对窗口根目录），页面按文件树的方式打开；
  - `attachment` / `blocked`：带 `reason`，页面显示在状态栏；
  - `handled` / `cancelled`：Go 已经做完（打开浏览器、开了新窗口）或用户取消，页面不用处理。
- **确认**：外链与工作区外文件由 Go 弹原生对话框，按钮为"取消 / 打开"，默认按钮是"取消"（回车不会误开）。
- **拒绝**：`javascript:`、`data:`、`file:`、自定义协议、绝对路径、`../` 越界的链接一律 `blocked`，不会读取文件、不会联网。

### WindowService.OpenTreeFile

- **TS**：`WindowService.openTreeFile(rel: string, newWindow: boolean): Promise<OpenRequestResult>`。
- **用途**：文件树里点开的文件。`rel` 是相对窗口根目录的路径，Go 用 `pathguard.Within` 判范围，越界返回 `out_of_scope`。
- **行为**：`newWindow` 为 false 时在当前窗口打开并返回 `kind: "file"`；为 true 时新开窗口、把文件作为请求交给它，返回空 `kind`，当前窗口的目录上下文不变（PRD FR-02.4、AC-06）。

### WindowService.OpenFolderDialog

- **TS**：`WindowService.openFolderDialog(): Promise<OpenFolderResult>`；组件通过 `transport.openFolder()` 调用。
- **用途**：弹出系统文件夹对话框，用户选中的文件夹即窗口的工作区根（PRD FR-03）。成功后窗口记录根目录，供 `Scan` 使用。
- **返回 `OpenFolderResult`**：`root`（规范化后的绝对路径）、`name`（文件夹名）；`root` 为空表示取消；`failure` 为可预期问题（`not_found`、`permission`、`unsupported_type`、`out_of_scope`）。

### WindowService.Scan

- **TS**：`WindowService.scan(frames: Channel<ScanFrame>): Promise<void>`；组件通过 `transport.scan(onFrame)` 调用。
- **用途**：把窗口当前根目录的文件树分批推给页面（每帧最多 500 条），最后一帧 `done: true` 并带结果。页面关闭 Channel 即停止扫描。
- **`ScanFrame`**：`entries`（TreeEntry[]）、`done`（boolean）、`truncated`、`bound`（`entries` / `markdown` / `depth`）、`skipped`、`failure`（没有打开文件夹时为 `no_folder`）。
- **`TreeEntry`**：`path`（相对根目录、斜杠分隔）、`name`、`isDir`。
- **规则**：只含 Markdown 与通向它们的目录；不跟随链接与目录联接；自然排序；5 万条目 / 1 万份 Markdown / 深度 64 为上限。

### WindowService.OpenFileDialog

- **TS**：`WindowService.openFileDialog(): Promise<LoadResult>`；组件通过 `transport.openFile()` 调用。
- **用途**：弹出系统文件对话框，用户选中的文件即授权（PRD FR-06.1）；随后在 Go 侧规范化路径、校验扩展名、按 10 MiB 上限读取并校验 UTF-8，再渲染为白名单 HTML（单次渲染 8 秒超时）。
- **返回 `LoadResult`**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `doc` | Doc，可选 | 读取成功时的文档 |
| `failure` | Failure，可选 | 可预期的问题；两者都为空表示用户取消 |

`Doc`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 文件名（含扩展名） |
| `path` | string | 规范化后的完整路径，只用于状态栏悬停和后续刷新 |
| `size` | number | 文件字节数 |
| `hasBom` | boolean | 原文件是否带 UTF-8 BOM |
| `lineEnding` | string | `LF` 或 `CRLF` |
| `text` | string | Markdown 源文，已去除 BOM、CRLF 统一为 LF |
| `html` | string | Go 侧渲染并经白名单清理的 HTML，页面直接注入显示。原始 HTML 以文本形式出现在 `pre.raw-html` / `code.raw-html` 中；代码块是 `div.code[data-lang]`，内含 chroma 的 `pre.chroma` 与短类名 token；标题带 `id`（保留中文，重复加 `-1`）；front matter 是默认折叠的 `details.fm` |
| `counts` | Counts | 本篇的公式与图表数量，含因超限未增强的数量（M3 起状态栏使用） |

文档里的本地图片在 `html` 中以 `http://mtres.localhost/<token>` 出现：token 由 Go 在渲染时登记，只对当前窗口、当前文档有效；页面向该地址请求时由 `mtres` 协议处理器按文件头校验格式（PNG / JPEG / GIF / WebP）、大小（≤ 20 MiB）与像素（≤ 2500 万）后返回。不能显示的图片（远程、越界、不存在、格式不支持、超限）会替换成 `div.limited[data-kind=image][data-reason]`，里面是 alt 文本。

`Counts`：`math`、`mathLimited`、`mermaid`、`mermaidLimited`（均为 number）。文档里的公式是 `span.math[data-display=false]` 与 `div.math[data-display=true]`，图表是 `pre.mermaid-src`，超限块是 `div.limited[data-kind][data-reason]`。

- **error**：来源窗口无效时同 `Ready`；对话框本身出错属意外故障，返回 Go error。
- **副作用**：成功后窗口记录当前文件（`winctx.Window.SetOpenFile`），供后续刷新与启动恢复使用。

### WindowService.NewWindow

- **TS**：`WindowService.newWindow(): Promise<NewWindowResult>`；组件通过 `transport.newWindow(): Promise<Outcome<void>>` 调用。
- **用途**：再开一个窗口（PRD FR-02）。M2-2 引入"空白窗口复用"矩阵后，矩阵只影响打开文件与目录；工具栏"新建窗口"与 `Ctrl+Shift+N` 始终新开。
- **返回 `NewWindowResult`**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `windowId` | number | 新窗口的 ID；有 `failure` 时为 0 |
| `failure` | Failure，可选 | 创建失败时的 `window_failed` |

- **error**：来源窗口无效时同 `Ready`。创建失败属可预期失败，放在 `failure` 里，不抛错。
- **副作用**：新窗口在创建时注册进 `internal/winctx`，它的 `Context()` 在关窗时取消。旧窗口不受影响。

## 3. 错误码

| 码 | 出现处 | 含义 |
| --- | --- | --- |
| `window_failed` | `WindowService.NewWindow` | 新窗口创建失败，界面在发起窗口提示，不影响已有窗口 |
| `not_found` | `OpenFileDialog` | 文件不存在、已被移动，或路径无法解析 |
| `permission` | `OpenFileDialog` | 没有权限读取 |
| `too_large` | `OpenFileDialog` | 超过 10 MiB，带 `size` 与 `limit` |
| `encoding` | `OpenFileDialog` | 非法 UTF-8，提示转换为 UTF-8 |
| `unsupported_type` | `OpenFileDialog` | 不是 `.md` / `.markdown`（大小写均接受），或选中的是目录 |
| `out_of_scope` | `OpenFileDialog` | UNC、设备路径或经过链接/联接的路径 |
| `request_expired` | `OpenRequested` | 请求已处理过且窗口没有可返回的内容 |
| `no_folder` | `Scan` | 窗口还没有打开文件夹 |
| `scan_failed` | `Scan` | 文件夹无法读取 |
| `render_timeout` | `OpenFileDialog` | 渲染超过 8 秒，界面保留可操作并允许重试 |
| `render_failed` | `OpenFileDialog` | 解析器报错或内部 panic，已捕获，不崩溃 |

M1-3 起继续登记。已在 skill 中约定的码（`mygo-web-app/references/bindings-and-channels.md` §2）：`not_found`、`permission`、`too_large`、`encoding`、`out_of_scope`、`unsupported_type`、`render_timeout`、`queue_full`。每个码到文案的映射集中在 `src/lib/errors.ts`。

## 4. 事件

| 名称 | 载荷 | 何时发出 | 接收方 |
| --- | --- | --- | --- |
| `open-request` | `OpenRequest` | 窗口已就绪后又来了打开请求 | 只发给目标窗口（`Event.Emit(win, …)`），不用 `Broadcast` |

- 事件只是"有新请求"的提示，不是唯一投递渠道：请求留在 Go 侧队列里直到 `Ack`，事件丢了也不会丢请求。页面收到事件后按 `seq` 去重再处理。
