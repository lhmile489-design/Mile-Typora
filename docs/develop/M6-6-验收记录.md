# M6-6 验收记录：受控开发者工具

> 对应 `docs/P3-高级工具需求.md` §3.6，验收项 P3-AC-12、P3-AC-13、P3-AC-15、P3-AC-16。

## 1. 交付内容

| 能力 | 实现 |
| --- | --- |
| 设置开关 | 设置对话框「诊断」组新增「诊断模式」复选框（默认关，`appstate.Settings.DiagnosticMode *bool`，老文件无字段默认 `false`）；风险文案注明"开启后，本机页面内容与脚本状态可被查看和修改，并恢复浏览器自带按键（F5 刷新、Ctrl+P 打印等）；不开启远程调试端口。保存后重启应用生效" |
| 生效模型 | mygo 在**窗口创建时**由 `PageOptions.DevTools` 决定，运行中改设置不追溯已开窗口——唯一生效模型是重启。`main.go` 新增 `windowDevTools()`：开启返回 `DevToolsEnabled`，关闭返回 `DevToolsAuto`（生产构建同样关闭，保留 `bun run dev` 与 `native-eval.mjs` 调试通道；契约写 `DevToolsDisabled` 的偏离记录于 D-T62） |
| 打印视图隔离 | 打印视图/导出临时窗口固定 `DevToolsDisabled` + `Untrusted`，不随设置变化；`OpenDevTools` 命中 `isPrintWindow` 直接返回 `devtools_unavailable` |
| 菜单与快捷键 | 视图菜单新增「开发者工具」子项（`Shift+F12`），未开诊断模式时 `aria-disabled` 且 `title` 提示「先在设置中开启诊断模式并重启」；快捷键用 `Shift+F12` 而非 `F12`，因为 `DevToolsEnabled` 会恢复 WebView2 自带的 F12/F5/Ctrl+P/Ctrl+F |
| Go 侧再校验 | `WindowService.OpenDevTools` 用 `CallerWindow` 定位（不信前端窗口 ID），打印视图返回 `devtools_unavailable`，诊断模式关或缺注入函数返回 `devtools_disabled`；页面菜单置灰是 UX，Go 校验才是底线，防伪造页面绕过 |
| 变更通知 | `contract.SettingsChange` 新增 `diagnosticModeChanged` 布尔标志（不带取值），让其他窗口只提示「重启后生效」而不覆盖本地显示；页面 `transport.saveSettings` 在保存前先 `getSettings` 比对得出自己窗口的 `diagnosticChanged` |
| 边界 | 不设置 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`、不开远程调试端口、不接外部 CDP——检查器只是本机 WebView2 的自带工具 |

## 2. 自动验证

| 命令 | 结果 |
| --- | --- |
| `go vet ./...` + `go test ./...` | 255 项通过，14 个包 |
| `bun run typecheck` | 通过 |
| `bunx vitest run` | 408 项通过，26 个文件 |
| `bun run build:web` | 通过，保留既有大分包警告 |

覆盖点：

- `internal/service/view_test.go`（3 项）：未开诊断模式 → `devtools_disabled` 且不调用打开函数；打印视图（`isPrintWindow` 命中）→ `devtools_unavailable`；已开诊断模式 → 调用注入的 `openDevTools` 并传入调用窗口 ID。
- `src/app/App.test.tsx`（3 项）：未开诊断模式时菜单项 `aria-disabled` 且 `title` 为提示文案；开启诊断模式的设置下菜单项可用、点击与 `Shift+F12` 各调用 `transport.openDevTools` 一次；`openDevTools` 返回失败时状态栏显示后端提示文案。

## 3. 原生验收

待用户在真实 Windows 11 窗口验收（`bun run dev`，5273，或发布构建）：

| 操作 | 预期 |
| --- | --- |
| 设置 → 诊断 → 勾选「诊断模式」→ 保存 | 状态栏提示「诊断模式已更改，重启后生效」；设置持久化 |
| 不重启，视图菜单 | 「开发者工具」仍按当前会话的 `diagnosticMode` 显示（新开窗口才生效） |
| 重启应用（诊断模式已开）→ 视图 → 开发者工具 / `Shift+F12` | WebView2 检查器打开；再次 `Shift+F12`/菜单同一命令 |
| 开启诊断模式后按 `F12` / `F5` / `Ctrl+P` | WebView2 自带按键恢复（检查器/刷新/打印），这是契约内已知行为 |
| 诊断模式关闭（默认）重启 → 视图菜单 | 「开发者工具」置灰，悬停显示「先在设置中开启诊断模式并重启」 |
| 打印视图（打印/导出 PDF 预览） | 检查器不可打开（始终 `DevToolsDisabled`） |
| 生产构建（`bun run build` 产物）诊断模式关闭 | 检查器与 WebView2 快捷键均不可用；无远程调试端口监听 |

## 4. 边界与未覆盖

- 生效模型是**重启**：保存设置后已开的窗口不变，只有下次启动建的窗口按新设置走。契约明确接受这一点（「保存后显示'重启后生效'」）。
- 关闭时用 `DevToolsAuto` 而非契约字面的 `DevToolsDisabled`：Auto 在生产构建同样禁用、但保住开发期调试通道。偏离已记于 decisions.md D-T62。
- `Shift+F12` 而非 `F12`：`DevToolsEnabled` 恢复 WebView2 自带 F12，F12 留给系统检查键避免冲突。
- 真实的检查器开合、打印视图拒绝、诊断模式持久化跨重启、`F12`/`F5`/`Ctrl+P` 恢复行为均需在真实 Windows 11 窗口验收；jsdom 无法驱动 WebView2 原生检查器。
