# M6-5 验收记录：代码工具

> 对应 `docs/P3-高级工具需求.md` §3.5，验收项 P3-AC-11。

## 1. 交付内容

| 能力 | 实现 |
| --- | --- |
| 菜单位置 | 段落菜单新增「代码工具」子菜单（无默认快捷键），只在源码编辑模式且光标/选区落在围栏代码块内时启用；选区跨围栏边界时禁用并显示原因 |
| 缩进整理（2 / 4 空格） | `reindent(snapshot, width)` 把每个正文行行首制表符按下一 4 列制表位展开成列数，换算为 `round(列/4)` 级，重写成 `级 × width` 空格；公共前导缩进自然保留（每行仍按自身级别缩进，不归零）；空白行不动；fence 行与行内空白不改；`makefile`/`make` 块禁用并显示「Makefile 配方行必须保留制表符」 |
| 转换为制表符缩进 | `toTabs(snapshot)` 只把行首缩进列数为 4 的倍数的行改写为 `\t`；不可整除行保持原样并在状态栏提示未转换行数；makefile 块仍可用（本身已是 tab） |
| 代码块语言名小写 | `lowercaseLanguage(snapshot)` 只改写围栏 info 串第一个 token 为小写；未知语言、无 info、已小写均返回 null 不标脏 |
| 判定与边界 | `codeFences` 自扫围栏（跳过 front matter、匹配同字符/更长 closing、未闭合跑到文末）；`fenceAt` 区分 `ok` / `cross` / null；跨边界选区由 `EditorContext.crossFence` 上报用于禁用项原因，命令本身也返回 false |
| 撤销语义 | 每个命令一次 `applyEdit` 一个事务 = 一步 Ctrl+Z；无变化返回 null 不标脏、不改文档 |
| 编辑器上下文 | `EditorContext` 新增 `inFence`/`fenceLanguage`/`crossFence`，由 `codeContextAt` 在 `updateListener`、初始与焦点上报中计算 |

## 3. 原生验收

待用户在真实 Windows 11 窗口验收（`bun run dev`，5273）：

| 操作 | 预期 |
| --- | --- |
| 光标放进 ```` ```ts ```` 围栏正文 → 段落 → 代码工具 | 子菜单四项可用 |
| 选「缩进整理（2 空格）」于含 tab 的块 | 行首 tab 展开为 4 列层级，重写成 2 空格倍数；Ctrl+Z 一步撤销 |
| 选「缩进整理（4 空格）」 | 同上，步进 4 空格 |
| 在 ```` ```makefile ```` 块 | 两条缩进整理禁用，提示「Makefile 配方行必须保留制表符」；制表符转换仍可用 |
| 缩进含 6 列（非 4 倍数）行的块 → 转换为制表符缩进 | 4 的倍数行转 tab，其余保留，状态栏提示「N 行缩进不是 4 的倍数，已保留原样」 |
| ```` ```TS {opts} ```` → 代码块语言名小写 | 变为 ```` ```ts {opts} ````，其余 info 保留 |
| 选区从围栏内拖到围栏外 | 菜单禁用，命令不执行 |
| 光标在普通段落 / 缩进代码块 | 菜单禁用（缩进代码块不处理） |
| 对无变化文档执行命令 | 不产生脏标记 |

## 4. 边界与未覆盖

- 只处理围栏代码块正文行；缩进代码块、行内代码不处理。
- 「缩进整理」按每行 `round(列/4)` 换算成层级再重写，非整除列（如 6 列）向最近 4 列层级靠拢；不做语言级格式化、不执行代码、不引入外部格式化器（契约 §3.5 已冻结）。
- 空白行保留原有空白；代码块内行尾空格不属于本工具范围（与 M5-8 行尾清理正交）。
- 语言名小写只对内置已知语言表内的 token 生效；未收录的语言保持原样。
- 跨围栏边界的选区：菜单禁用并显示原因；命令调用也直接返回不执行（双保险）。
- 真实键入后的菜单启用状态、makefile 交互与状态栏提示待用户桌面验收。
