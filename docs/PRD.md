## 1. 产品概述

### 1.1 背景与定位

面向需要阅读本地 Markdown 文档的用户，提供接近 Typora 的简洁阅读体验，但不将 Typora 的完整功能作为首版范围。

用户可以直接预览单个 Markdown 文件，可以重复创建独立窗口并行阅读多个文件，也可以打开一个目录，在左侧文件树中浏览该目录及子目录下的 Markdown 文件，在中间阅读正文。右侧预留未来 Agents 扩展区域，首版不接入智能体能力。

本产品是本地桌面应用。React 仅用于 mygo 内嵌界面，不交付独立浏览器版本，不需要启动面向用户的 Web 服务。

### 1.2 版本定义

- **P0：完整阅读版本。** 完成只读预览、独立多窗口、目录浏览、公式与 Mermaid 渲染、可手动调整的启动设置及必要异常处理。
- **P1：基础编辑版本。** 增加 Markdown 编辑、保存、常用段落 / 格式命令、基础编辑菜单及配套的数据安全机制。
- **P2：效率与高级排版版本。** 增加文件管理、高级段落 / 格式工具、导出打印、阅读视图与显示设置。
- **P3：高级工具与生态版本。** 增加格式导入、高级编辑辅助、数学工具及诊断工具等。
- **未排期探索：** Agents、云同步、协作等，不因出现 P3 而自动纳入 P3。

本文的 P0–P3 表示交付阶段，不另作同名优先级分类；具体菜单归属见第 15 节。

## 2. 用户、场景与目标

### 2.1 目标用户

- 阅读 README、技术方案、项目说明和本地知识笔记的开发者。
- 以目录组织 Markdown 资料，需要连续切换阅读的个人用户。
- 需要同时查看多份资料、跨窗口对照内容的用户。

### 2.2 核心场景

| 场景 | 用户操作 | 预期结果 |
| --- | --- | --- |
| 单文件阅读 | 在应用中选择一个 `.md` 文件 | 在阅读窗口中显示排版后的正文 |
| 多文件对照 | 保留 A，继续打开 B、C | A、B、C 可处于不同原生窗口，互不覆盖 |
| 同文件多视角 | 将 A 再次在新窗口中打开 | 两个窗口均显示 A，可以停留在不同阅读位置 |
| 目录阅读 | 选择一个文档目录 | 左侧显示 Markdown 文件树，点击文件在中间展示 |
| 目录与独立阅读并行 | 在文件树中将某文件在新窗口打开 | 原目录窗口保持不变，新增独立文件窗口 |
| 外部编辑后阅读 | 在其他编辑器保存当前文件 | 阅读器更新预览，尽量保留阅读位置 |
| 继续上次阅读 | 设置“恢复上一份文档”后重启 | 只恢复最近阅读的一份文档及必要目录上下文 |
| 每次空白启动 | 设置“打开新的空白页”后重启 | 显示打开入口，不自动加载历史文档、不创建磁盘文件 |
| 阅读技术图文 | 打开包含数学公式和 Mermaid 的文档 | P0 即可离线显示排版后的公式和受支持图表 |

### 2.3 P0 目标与成功标准

1. 不依赖编辑模式即可完成单文件和目录阅读。
2. 真正支持多个可独立移动、缩放、最小化和关闭的原生窗口，不以标签页或页面内浮层代替。
3. 同一目录中，包括子目录中的 Markdown 文件，都有明确的浏览入口；达到容量边界时明确提示，不静默遗漏。
4. 读取不修改源文件，也不因查看任务列表等交互写回内容。
5. 本地文档及本地图片可以离线阅读，不向 Agents 或云端上传内容。
6. 数学公式、受支持 Mermaid 图表可以离线渲染；局部语法错误不导致整篇阅读失败。
7. 启动行为由用户在设置中手动选择并持久化，而不是固定空白或固定恢复。

## 3. 版本范围

### 3.1 功能清单

| 模块 | P0：完整阅读 | P1：基础编辑 | P2：效率与排版 | P3：高级工具 |
| --- | --- | --- | --- | --- |
| 打开内容 | 单文件、单目录、最近打开 | 快速打开；多选 / 拖放 / 文件关联作为候选另行确认 | 不扩展平台范围 | 格式导入 |
| 多窗口 | 原生多窗口、同文件重复打开 | 跨窗口编辑冲突、保存全部 | 应用内区域焦点切换、窗口置顶 | 不默认增加标签页 |
| 文件树 / 文件管理 | 递归树、展开折叠、刷新 | 快速打开按文件名匹配 | 移动、回收站删除、属性、定位、目录搜索 | 不默认加入云文件系统 |
| 阅读渲染 | CommonMark / GFM、公式、Mermaid、本地图片、锚点、文内查找 | 与编辑预览共用渲染器 | 脚注、警告框、正文目录等扩展及配套编辑 | 不承诺任意自定义插件 |
| 编辑保存 | 不提供 | 新建、编辑、保存 / 另存为、撤销重做、基础段落 / 格式、查找替换 | 表格 / 图片 / 高级段落工具、扩展格式 | 智能标点、拼写、数学及高级代码工具 |
| 启动与状态 | 可选恢复上一份 / 新空白页、浅色 / 深色 / 跟随系统外观、最近记录、少量设置 | 新空白页可成为未保存的新文档 | 大纲、文档列表、专注等视图、缩放和更多内置主题 | 完整多窗口会话恢复仍未排期 |
| 输出 | 无导出 / 打印 | 剪贴板复制 Markdown | HTML / PDF 导出、打印 | 其他交换格式先评估再确认 |
| 右侧 / 平台 | 右侧空白预留；Windows 11 x64 | 不默认加入 Agents 或其他平台 | 同左 | 同左 |

P1–P3 的菜单分配是本轮需求下的建议实施路线，阶段内的功能边界见第 15 节，不构成发布日期承诺。Agents、云同步、实时协作、独立 Web 版、其他操作系统和完整多窗口会话恢复仍未排期。

### 3.2 P0 明确不做

- 不支持输入、修改、保存、自动保存或格式化 Markdown 源文件。
- 不支持文件或目录的新建、重命名、移动、复制、删除。
- 不引入账号、登录、云空间、云同步、遥测或第三方分析服务。
- 不接入 Agents、模型服务、API Key、向量库或文档索引服务。
- 不实现 PDF / HTML 导出、打印、Git 管理、插件市场和实时协作。
- 不承诺与 Typora 的全部 Markdown 扩展语法、主题和交互完全兼容。
- 不支持网络共享目录、UNC 路径、网络资源盘的稳定性验收；P0 以本地磁盘为准。

## 4. 建议默认决策

以下方案用于消除开发歧义；用户可以在评审时修改，不阻塞 PRD 交付。

| 决策编号 | 建议默认值 | 原因 |
| --- | --- | --- |
| D-01 | 首发 Windows 11 x64 | 控制第一版原生兼容性范围 |
| D-02 | 一个窗口只维护一个目录工作区或一个单文件阅读上下文 | 降低多窗口状态复杂度 |
| D-03 | 打开文件 / 目录优先复用当前空白窗口；非空白窗口发起打开时创建新窗口 | 避免新打开内容覆盖已有阅读现场 |
| D-04 | 显式“在新窗口打开”始终创建新窗口，即使目标文件已经打开 | 满足重复打开和对照阅读 |
| D-05 | 目录范围包含所有子目录，识别 `.md`、`.markdown`，扩展名大小写均可 | 明确“目录下都能看到”的范围 |
| D-06 | 右侧预留栏默认收起，可随时展开；窗口宽度不足时也不占位 | 阅读优先，预留栏在接入 Agents 前没有内容（v0.4 调整） |
| D-07 | 已由 C-12 取代（v0.3）：P0 提供浅色、深色与跟随系统三种外观；更多内置主题与自定义主题后续规划 | 用户评审确认 P0 开放深色；原建议“P0 只用浅色”不再适用 |
| D-08 | P0 支持 CommonMark / GFM、数学公式及 Mermaid；具体语法和图表范围见 FR-04 | 执行已确认的渲染前移，避免误解为所有扩展语法均兼容 |
| D-09 | 外部变更自动刷新，保留阅读位置；保留手动刷新入口 | 适配“外部编辑、应用阅读”流程 |
| D-10 | 默认不加载远程图片，不执行文档 HTML / 脚本 | 离线优先，防止文档引发隐私泄露和执行风险 |
| D-11 | 最近记录 20 项；启动可选恢复上一份文档或新空白页，首次默认新空白页；不批量恢复窗口 | 满足用户手动调整启动行为，同时保持恢复范围可控 |

## 5. 信息架构与页面布局

### 5.1 窗口结构

```text
┌────────────────── 系统标题栏 / 窗口控制 ──────────────────┐
│ 工具栏：打开文件｜打开目录｜新窗口｜刷新｜查找｜侧栏｜设置 │
├────────────┬──────────────────────────┬─────────────────┤
│ 左侧       │ 中间                     │ 右侧            │
│ 文件树     │ Markdown 正文            │ 空白预留区域    │
│            │ 独立滚动                 │ 可折叠          │
│ 独立滚动   │                          │ P0 无 Agents    │
├────────────┴──────────────────────────┴─────────────────┤
│ 状态栏：只读｜当前文件信息｜加载 / 变更 / 异常状态         │
└──────────────────────────────────────────────────────────┘
```

左侧“目录”指文件系统中的文件树，不是当前 Markdown 的标题大纲。标题大纲属于后续功能。

### 5.2 尺寸与滚动规则

- 建议初始窗口客户区为 1280 × 800，最小客户区为 960 × 640，均按逻辑像素计算。
- 左侧建议宽 240，右侧建议宽 260，中间占剩余空间；P0 不要求拖拽调整栏宽。
- 窗口宽度小于 1200 时自动收起右侧；恢复宽度后，仅在用户没有主动隐藏时恢复显示。
- 左侧可手动折叠，折叠不改变目录工作区和当前文件。
- 正文居中排版，建议最大内容宽度 860；侧栏收起时不无限拉长文本行。
- 文件树和正文分别纵向滚动，不出现整窗纵向滚动条。
- 代码块、宽表格可以局部横向滚动，不能撑破正文区域。
- 在 Windows 显示缩放 100%、125%、150%、200% 下不得出现关键操作无法访问的问题。

### 5.3 页面类型

| 页面 / 状态 | 左侧 | 中间 | 右侧 |
| --- | --- | --- | --- |
| 初始空白 | 空状态 | 打开文件、打开目录、最近打开 | 空白占位，按宽度规则显示 |
| 单文件模式 | 仅列出当前文件，不自动扫描父目录 | 当前文件正文 | 空白占位 |
| 目录未选文件 | 文件树 | “请从左侧选择 Markdown 文件” | 空白占位 |
| 目录阅读中 | 文件树和当前选中项 | 当前文件正文 | 空白占位 |
| 初次加载失败 | 保留可操作的导航区 | 错误说明、重试、重新选择入口 | 空白占位 |

右侧不显示聊天输入框、发送按钮、模型选择、假数据或“已连接 Agents”等暗示功能已可用的元素。折叠开关可用提示文字“预留侧栏”。

P0 通过工具栏提供所需入口及设置；P1 开始提供“文件 / 编辑 / 段落 / 格式 / 视图”菜单，后续阶段逐步补齐。未交付阶段的命令不在生产界面中伪装可用。截图只作为功能与快捷键参考，不要求复刻外观。

## 6. P0 功能需求

### FR-01 打开单个 Markdown 文件

**入口：** 工具栏、空白页“打开文件”、快捷键 `Ctrl+O`、最近打开记录。

1. 使用系统文件选择器，P0 每次选择一个文件。
2. 支持 `.md` 和 `.markdown`，包括大写扩展名；其他类型给出“不支持的文件类型”，不能当作 Markdown 强行打开。
3. 打开成功后显示文件名、可查看的完整路径和“只读”标识；长路径截断时仍可通过悬浮提示查看。
4. 空白窗口内打开直接进入单文件模式；从非空白窗口发起时在新窗口打开。
5. 取消选择器不改变任何已有内容，不新增空白窗口，不增加最近记录。
6. 空文件属于有效文档，显示“这是一个空 Markdown 文件”，不报加载错误。
7. 首次读取失败不进入最近记录；无法读取时给出重试和重新选择入口。

**验收：** 用户打开中文文件名、包含空格的本地路径和空文件，均获得正确且可解释的结果，源文件字节不发生变化。

### FR-02 独立多窗口与重复打开

**入口：** 工具栏“新建窗口”、`Ctrl+Shift+N`、文件树菜单“在新窗口打开”。

1. 新建窗口先创建独立空白阅读窗口。
2. 文件树或正文关联 Markdown 链接提供显式的新窗口打开方式。
3. 显式新窗口操作不得因为文件路径已打开而只聚焦旧窗口。
4. 每个窗口分别维护当前文件、目录根、树展开状态、阅读位置、查找词和侧栏显隐。
5. 文件树点击只切换当前目录窗口的正文，不修改其他窗口。
6. 同一个文件可被多个窗口读取，各自滚动独立；文件内容的外部变更应通知所有相关窗口。
7. 关闭窗口仅释放该窗口的任务和订阅，不使其他窗口丢失内容或无法刷新。
8. P0 不使用常驻托盘；最后一个窗口关闭后退出应用。
9. 不规定产品层面的固定窗口上限，但至少以 10 个并行阅读窗口验收。系统资源不足时明确提示创建失败，保留已有窗口。

**窗口行为矩阵：**

| 操作 | 当前窗口情况 | 结果 |
| --- | --- | --- |
| 打开文件 / 目录 / 最近记录 | 空白 | 复用当前窗口 |
| 打开文件 / 目录 / 最近记录 | 已有文件或目录 | 创建新窗口 |
| 打开文件 / 目录 / 最近记录 | 目标与当前已打开的文件或目录相同 | 仍按非空白规则创建新窗口，不隐式去重 |
| 新建窗口 | 任意 | 创建新的空白窗口 |
| 文件树单击或键盘确认 | 目录窗口 | 在当前窗口显示目标文档 |
| 在新窗口打开 | 任意 | 始终创建目标文件的独立窗口 |
| 同一个文件再次显式新开 | 该文件已在其他窗口打开 | 仍然新建，不去重 |

**验收：** A、B、A 分别在三个原生窗口中打开，第一和第三个窗口停在不同段落；关闭任意一个不影响另外两个。

### FR-03 打开目录与文件树

**入口：** 工具栏、空白页“打开目录”、`Ctrl+Shift+O`、最近打开记录。

1. 使用系统目录选择器，一次选一个根目录；窗口复用规则同 FR-02。
2. 树根显示目录名称；完整路径可通过悬浮提示查看。
3. 递归展示 Markdown 文件及包含这些文件的祖先目录，不展示图片、代码等非 Markdown 文件。
4. 不读取全部正文来构建树；仅在选择文件时读取并渲染正文。
5. 普通隐藏目录和点号目录也在扫描范围内，不默认套用 `.gitignore`；空目录和没有 Markdown 后代的目录不显示。
6. 不跟随目录内的符号链接、目录联接或其他重解析入口，避免循环和越出目录范围；以状态提示告知存在跳过项。
7. 同级目录在前、文件在后，名称按不区分大小写的自然排序显示；同名文件依靠目录层级区分。
8. 支持展开、折叠、单击选择；首次打开目录不自动选择文档，保持“请从左侧选择”状态。
9. 返回已读文件时恢复本窗口中的阅读位置；若内容变化，按可用锚点或相对滚动位置回退。
10. 扫描中显示进度状态；无 Markdown 时显示“此目录下未找到 Markdown 文件”，与权限错误区分。
11. 部分子目录不可读时展示已成功扫描的部分，并明确标注“部分目录无法访问”，可重试；禁止伪装成完整结果。
12. 文件新增、删除、改名后更新文件树，并提供手动刷新作为补充。改名无法可靠识别时可按删除加新增处理，不要求跟踪文件身份。
13. 扫描达到容量上限时停止继续遍历，显示“结果不完整，请打开更小的子目录”，保留已展示结果，不静默截断。

**验收：** 根目录、至少 5 层嵌套目录、中文路径、同名文件、隐藏目录、部分无权限目录均有可解释的展示结果。

### FR-04 Markdown 渲染与只读交互

| 内容类型 | P0 要求 |
| --- | --- |
| 基础排版 | 支持 CommonMark 范围内的标题、段落、换行、引用、分隔线、强调、行内代码、围栏代码块、缩进代码块、有序 / 无序列表 |
| 常用 GFM | 支持表格、删除线、任务列表和自动链接 |
| 任务列表 | 保留勾选状态，但复选框不可修改，也不写回文件 |
| 代码块 | 保留缩进和换行，提供常见语言高亮及复制；未知语言按纯文本展示 |
| 图片 | 支持相对路径的本地 PNG、JPEG、GIF、WebP；遵守 FR-06 的资源范围限制 |
| 标题锚点 | 支持文内跳转；重复标题生成可区分锚点，规则保持稳定 |
| 文字选择 | 支持鼠标选择、复制，不拦截常规复制操作 |
| 原始 HTML | 不作为可执行 HTML 渲染，以转义后的文本展示 |
| YAML front matter | 文档开头合法 front matter 折叠为只读元信息块，可展开查看；不执行内容 |
| 数学公式 | P0 渲染行内和块级 LaTeX 公式；语法、离线和安全边界见下文 |
| Mermaid | P0 将受支持的 `mermaid` 围栏代码块渲染为图表；范围与错误回退见下文 |
| 其他未支持扩展 | 尽量保留可读文本，不导致整篇渲染失败 |

普通相对资源以当前 Markdown 所在目录为解析基准，而不是以应用目录或工作区根目录为基准。包含中文、空格和 URL 编码字符的资源路径应有统一且可测试的解码规则，禁止多次解码绕过路径检查。

**编码：** 支持 UTF-8 和带 BOM 的 UTF-8 输入，兼容 CRLF / LF；P0 不自动猜测 GBK、UTF-16 等编码。检测到不合法 UTF-8 时提示转换编码后重试，不用乱码内容替代成功状态。

**数学公式渲染（P0）：**

1. 支持 `$...$` 行内公式、`$$...$$` 块级公式，以及 `\(...\)`、`\[...\]` 等价分隔形式；代码块、行内代码及转义的美元符号不作为公式解析。
2. 首版覆盖上下标、分数、根式、求和、积分、矩阵、常用数学符号及多行对齐；渲染引擎及支持的 LaTeX 命令清单在技术验证时锁定，不承诺完整 TeX 环境。
3. 不启用信任模式、自定义可执行宏、HTML 注入、外部资源加载或命令执行；遇到不支持命令和语法错误，局部显示原公式及原因，其余正文正常阅读。
4. 公式字体与依赖随应用打包，断网可渲染；独立窗口各自维护展示状态，不改变原文件。

**Mermaid 渲染（P0）：**

1. 初始图表集为流程图、时序图、类图、状态图、实体关系图和甘特图；使用 `mermaid` 围栏代码块声明，含中文标签的上述图表纳入验收。
2. 其他图类型或超出锁定版本的语法显示原代码与“不支持的图表类型 / 语法”提示，不导致整篇失败；更多图类型在 P2 评估扩展，不自动承诺 Mermaid 全量兼容。
3. 仅在本地以严格安全配置渲染；禁用图表点击回调、脚本、远程资源和 HTML 标签，不接受文档内指令降低安全级别或修改全局配置。
4. 宽图表在自己的区域内滚动；保留查看 / 复制源码入口，不在 P0 提供图表编辑或导出。
5. 图表错误、超限或超时仅降级对应代码块，不让正文白屏。渲染结果若采用 SVG，必须由受控渲染器生成并通过清理，不允许任意用户 SVG 注入。

**局部降级与版本协同：** 公式 / 图表局部降级属于“正文可读、部分内容渲染受限”，不等于 FR-07 的整份文档刷新失败。P1–P3 的“插入公式 / 代码块 / 扩展格式”属于编辑命令，不能因排到后续阶段而后移本节已确认的 P0 阅读渲染。

### FR-05 文内导航与查找

1. `Ctrl+F` 打开当前正文的查找条；范围仅限当前文档，不检索目录中的其他文件。
2. 按渲染后的可见文本进行字面查找，不支持正则；默认不区分英文大小写。
3. 显示命中总数与当前序号，支持上一个 / 下一个、Enter / Shift+Enter 切换、Esc 关闭。
4. 无结果时明确显示“未找到匹配内容”。切换文件后清空查找词，避免把上一文档结果带到新文件。
5. 文内标题锚点在当前窗口滚动；锚点不存在时轻提示，不跳到无关位置。
6. 正文存在可读正文但查找无结果，不等同于文件为空。
7. P0 查找覆盖普通渲染文字与代码文本，不承诺命中公式排版内部结构、图表节点及隐藏源码；此限制在查找提示中说明。

### FR-06 链接与资源访问边界

**本地授权范围：** 目录模式为用户选择的根目录及其普通子目录；单文件模式为该文件及其父目录范围内的相对图片资源，不因此扫描或展示父目录文件树。

1. 本地资源在 Go 侧完成规范化、真实路径解析和范围校验。不能仅依赖前端字符串判断或路径前缀判断。
2. 目录内 Markdown 相对链接：在当前目录窗口中切换文件，并保留文件树；附带锚点时在加载后定位。
3. 单文件模式下的其他 Markdown 链接：经用户确认后在新的单文件窗口打开，不把当前窗口变为目录模式。
4. 目录模式下指向工作区外的 Markdown 链接：先提示目标路径并请求确认，同意后新建单文件窗口；拒绝不读取目标内容。
5. 同文档锚点留在当前窗口；显式“在新窗口打开”仍按 FR-02 执行。
6. 相对图片必须落在授权范围内，路径解析后越界、绝对路径图片、UNC 图片和经重解析入口指向范围外的图片均不自动读取，显示占位和原因。
7. 本地图片附件不是文件树展示对象，但可作为正文的受控资源读取。
8. 远程 HTTP / HTTPS 图片在 P0 不请求，显示“远程图片未加载”；P0 不提供联网加载开关。
9. HTTP / HTTPS 文本链接点击后交由系统默认浏览器，不在应用内导航；本窗口首次打开某一来源时提示将访问外部站点，用户可取消。
10. 禁止执行 `javascript:`、`data:`、`file:`、自定义命令协议，以及 Markdown 内嵌脚本、事件处理器、iframe、可执行附件和 SVG 活动内容；P0 不读取或显示用户提供的 SVG 图片。FR-04 中由受控 Mermaid 渲染器生成并清理后的内部 SVG 不属于用户 SVG 附件，但同样不得含活动内容或网络资源。
11. 非 Markdown 本地文件链接提示“暂不支持打开此类附件”，不自动调用其他应用或执行文件。
12. 内嵌页面不得因为文档链接跳离应用页面；错误信息不得将未经授权文件的内容带回前端。

目录内链接的补充规则：目标经过容量截断、尚未完成扫描或权限失败而未列入文件树时，不强行展开或扩充当前树；提示用户确认后尝试在独立单文件窗口打开，实际读取仍须通过权限与大小检查。经过符号链接、目录联接等被跳过入口的目标在 P0 不沿原链接打开，提示用户通过文件选择器直接选择实际文件；确认对话框不能绕过这一限制。

### FR-07 外部修改与刷新

1. 监测当前打开文档及其目录结构的外部变化；同一个文件被多个窗口打开时，各窗口均应收到更新。
2. 外部编辑器原子替换保存、短时间连续写入时应合并变更，等待写入稳定后再读取，避免瞬态空白和频繁闪动。
3. 更新成功后保留窗口、目录选择和侧栏状态；阅读位置优先用稳定锚点恢复，失败后按原相对位置恢复并限制在有效范围。
4. 新内容为空时展示空文档状态，不能继续将旧内容显示成最新内容。
5. 文件被删除或短暂不可读时保留最后成功内容，但醒目标注“文件已不存在 / 当前内容可能已过期”，提供重试和关闭当前文档入口。
6. 文件树删除已选中项后，不擅自跳到另一个文件；中间保留上述过期内容状态。
7. 文档第一次从未加载成功时，不存在可回退正文，应显示完整加载错误。
8. `F5` / 工具栏刷新在目录模式下同时刷新文件树与当前正文，在单文件模式下刷新当前文件；无选中文档时只刷新树。
9. 目录根删除或磁盘断开时保留工作区上下文并提示不可用，可重试或重新选择目录，不导致其他窗口失败。
10. 快速连续切换文档时，旧加载结果不得覆盖后选文件；关闭窗口后不再投递渲染更新。
11. 已成功显示过的文档刷新失败，包括编码校验失败、文件增大超过上限或渲染失败，均保留最后成功内容并标注过期及失败原因；仅首次加载失败时显示完整错误页。保留旧内容不表示新版本已读取成功。

### FR-08 最近打开与本地状态

1. 最近打开列表记录最近 20 个文件 / 目录，按规范化目标去重、按最近成功打开时间排序，记录类型、名称和路径。
2. 最近记录的去重只影响列表，不影响同文件重复创建窗口。
3. 点击已不存在或无权限的记录时提示原因，允许移除此记录，不自动删除其他记录。
4. 支持清空最近记录；清空仅删除应用元数据，不删除源文件，也不关闭已打开窗口。
5. P0 在窗口生命周期内保留树状态和各文件阅读位置；跨重启只为 FR-10 的恢复目标保存必要目录上下文和近似阅读位置，不保证完整树展开态或所有历史文件位置。侧栏手动显隐偏好可作为新窗口默认值保存，已有窗口不被强制同步改变。
6. 重启按 FR-10 的启动设置，仅打开一个窗口，不批量恢复历史窗口。
7. 最近记录及设置可写入应用数据目录，不得写入用户文档所在目录。P0 的“只读”约束针对源文档与工作区内容，不禁止保存应用自身设置。
8. 应用元数据保存失败时非阻断提示，当前阅读仍可继续；不得把“历史已保存”作为虚假成功反馈。

### FR-09 快捷键与基础可访问性

| 快捷键 | 行为 |
| --- | --- |
| `Ctrl+O` | 打开文件 |
| `Ctrl+Shift+O` | 打开目录 |
| `Ctrl+Shift+N` | 新建空白窗口 |
| `Ctrl+F` | 当前文档查找 |
| `F5` | 刷新当前阅读上下文 |
| `Ctrl+C` | 复制已选文字；无选择时不复制整篇 |
| `Ctrl+W` / `Alt+F4` | 关闭当前窗口 |
| `Esc` | 优先关闭查找条或当前临时提示，不关闭文档 |
| `Ctrl+,` | 打开设置；逗号键，不是中文输入法标点 |

- `Ctrl+S` 在 P0 不触发 WebView 默认“保存网页”对话框，可轻提示“当前版本仅支持阅读”。
- 快捷键仅在应用窗口聚焦时生效，不注册全局快捷键。
- 文件树支持方向键移动、左右键展开折叠、Enter 打开；按钮有可见焦点及可读名称。
- Tab 焦点顺序清楚；状态和错误不可仅依赖颜色传达。

### FR-10 设置与启动行为

**P0 必做入口：** 工具栏“设置”、`Ctrl+,`。P1 增加“文件 → 偏好设置”菜单入口，复用同一设置能力，不重新实现另一套配置。

1. 在“设置 → 常规 → 启动时”提供两个互斥选项，可随时手动切换：**恢复上一份文档**、**打开新的空白页**。首次启动默认新空白页；此默认值为建议，不限制用户更改。
2. 设置为应用级偏好，多窗口看到同一已保存值；明确保存并持久化成功后才提示成功。取消不生效，写入失败保留之前的有效值并允许重试。
3. 启动设置只影响下次进程从关闭状态启动；不即时替换任何已打开文档，不改变 `Ctrl+O`、目录树切换或显式“新建窗口”的行为。
4. **上一份文档的定义：** 最近一次成功展示在前台窗口中的文档。成功切换正文或激活一个已成功加载文档的窗口时更新恢复目标；空白窗口、只打开但尚未选文件的目录、加载失败不覆盖有效目标。多个窗口按最后一次此类前台事件确定，不按文件修改时间或关窗顺序决定。
5. 恢复模式只创建一个窗口。目标原为目录模式时，恢复原根目录、选中文档及近似阅读位置；原为单文件模式时仅恢复该文件。不恢复其他窗口、查找词和完整树展开态。
6. 没有历史目标或目标文件 / 必需目录不存在、无权限、超限或编码无效时，回退到新空白页并说明原因，保留打开文件 / 目录入口，不阻塞启动，也不擅自改掉用户的恢复模式设置。
7. **新空白页的定义：** P0 显示打开文件 / 目录与最近记录入口，不创建或保存磁盘文件；P1 才可承载未保存的新文档，必须遵循未保存保护。
8. “新建窗口”始终空白，不自动恢复上一份，避免反复新建同一内容。未来系统文件关联或显式启动参数打开指定目标时，指定目标优先，不再额外恢复历史窗口。
9. 恢复时按照保存目标重新建立该目标的本地读取授权，仍须经过正常权限、真实路径、容量与渲染安全检查，不因历史记录绕过限制。
10. “清空最近记录”同时清除恢复目标、根目录上下文与持久化阅读位置，避免仍从历史路径恢复；不改变启动模式偏好，不删除文档、不关闭当前窗口。清空完成时保留的当前窗口不会立即回填目标，只有之后再次成功切换文档或重新激活文档窗口才生成新恢复记录。
11. 配置损坏时说明“设置无法读取，本次按默认空白页启动”，保留损坏文件供排查，不静默覆盖。下次成功保存偏好时再替换有效配置。
12. **外观（C-12）：** 在“设置 → 外观”提供三个互斥选项：**跟随系统**、**浅色**、**深色**。首次启动默认跟随系统（此默认值为建议）。保存成功后所有已打开窗口立即切换，不重新读取文档、不丢失阅读位置；公式随文字颜色变化，Mermaid 图表按新主题重新渲染。选择跟随系统时，Windows 外观变化后各窗口自动跟随。外观偏好与启动设置同属应用级偏好，同样适用第 2 条和第 11 条的保存失败与配置损坏规则；配置损坏时外观按跟随系统处理。启动和新建窗口不出现与所选外观相反的白闪或黑闪。颜色取值以 DESIGN.md 为准，两套主题都须满足其对比度要求。

**验收：** 用户可以在两个选项间来回切换并重启验证；A、B、A 三个窗口下切换前台后应恢复最终前台文档；首次启动、失效路径、清空记录、保存失败及“新建窗口”均有确定结果；外观三个选项可切换，多窗口即时生效并跨重启保留。

## 7. 状态、异常与消息

### 7.1 状态模型

- 窗口上下文：空白、单文件、目录工作区。
- 目录状态：未选择、扫描中、就绪、空目录、部分失败、扫描受限、根目录不可用。
- 文档状态：未选择、加载中、就绪、有效空文档、初次失败、保留旧内容但已过期。
- 正文可包含“公式 / 图表局部渲染受限”子状态，不覆盖其他成功渲染部分；启动恢复失败使用空白页加原因提示。
- 不同状态可以组合，例如“目录部分失败 + 当前文档就绪”，不能用单一错误页覆盖全部能力。

### 7.2 异常反馈矩阵

| 异常 | 用户可见反馈 | 恢复方式 |
| --- | --- | --- |
| 取消文件 / 目录选择 | 不报错、不改变阅读现场 | 保持原状态 |
| 文件不存在 / 无权限 | 显示具体类别，不显示堆栈 | 重试、重新选择 |
| 非 UTF-8 编码 | “暂不支持此文件编码，请转换为 UTF-8” | 外部转换后重试 |
| 文件超过读取上限 | 显示实际大小和支持上限 | 选择较小文件 |
| 文件渲染超时 / 失败 | 停止加载并显示可恢复错误 | 重试、关闭当前文档 |
| 目录内无 Markdown | 独立空状态 | 打开其他目录、刷新 |
| 目录部分权限失败 | 树可用，显示部分结果提示 | 重试、调整权限 |
| 目录扫描达到上限 | 明确标注结果不完整 | 打开更小子目录 |
| 图片不存在 / 被阻止 / 超限 | 图片位置显示原因与替代文字 | 修改外部资源后刷新 |
| 文件外部删除 | 保留旧正文并标注过期 | 重试、关闭当前文档 |
| 最近记录失效 | 提示目标不可用 | 移除记录、重新选择 |
| 新建窗口失败 | 在发起窗口提示，已有内容保留 | 关闭其他窗口后重试 |
| 应用设置写入失败 | 非阻断提示“本次设置未保存” | 继续阅读、稍后重试 |
| 公式 / Mermaid 语法错误或局部超限 | 对应位置显示原内容与原因，正文其余部分正常 | 外部修改后刷新 |
| 启动恢复目标失效 / 无权限 | 新空白页加恢复失败原因，不反复弹窗 | 手动打开其他目标或修改启动设置 |
| 启动设置损坏 | 说明本次使用默认空白页，保留原损坏配置 | 手动重新设置并成功保存 |

### 7.3 消息原则

日常状态使用状态栏或局部提示，操作错误使用就近提示；仅授权越界访问、跳转外部站点等决策使用确认对话框。P0 不发送系统通知、不在后台弹出 Agents 消息。

## 8. 非功能需求与容量边界

### 8.1 兼容性与离线运行

- 首版验收环境为 Windows 11 x64，使用系统 WebView2；缺少运行时应给出清晰安装引导，不得只显示白屏。
- 安装 / 获取 WebView2 可能需要额外网络条件；核心离线验收在运行时已安装的条件下进行。
- 应用字体、公式字体、Markdown / 数学公式 / Mermaid 渲染器和高亮资源随包提供，不通过 CDN 加载。
- 离线情况下可以打开本地文件、目录及授权范围内的本地图片；外部链接不属于离线能力。
- 不申请管理员权限作为日常阅读前提。

### 8.2 性能目标（建议验收值，尚未实测）

参考环境：Windows 11 x64、本地 SSD、至少 4 核 CPU、16 GB 内存。正式性能报告必须补充 CPU 型号、系统版本、WebView2 版本和测试样本，不能把下表写成已验证的事实。

| 指标 | 建议目标与测量口径 |
| --- | --- |
| 冷启动 | 新空白页模式从启动到空白页可操作，目标不超过 3 秒；恢复模式另记录从启动到文档可阅读耗时；至少 5 次独立冷启动逐次记录 |
| 普通文档打开 | 已启动应用，1 MiB 内、1 万行内、无极端复杂表格且不计图片解码，从确认打开到正文可阅读，20 次测试 P95 不超过 1.5 秒 |
| 已就绪目录切换 | 上述普通文档条件下，从选择到正文可阅读，20 次测试 P95 不超过 1 秒 |
| 目录首屏 | 1 万条总条目、最多 2000 份 Markdown 的样本目录，首批可操作树节点目标 1 秒内出现，完整扫描目标 5 秒内完成 |
| 外部变更 | 普通文档写入稳定后 2 秒内更新；自动更新失效时手动刷新仍可用 |
| 多窗口 | 至少 10 个各打开 100 KiB 普通文档的窗口，连续切换、滚动、关闭无崩溃或长期无响应 |
| 资源释放 | 关闭窗口后 5 秒内停止其专属读取任务并释放订阅；共享监听仅在仍有使用者时保留 |
| 公式与图表专项 | 在普通文档打开指标之外，独立测试包含 100 个行内公式、20 个块公式、6 个受支持 Mermaid 样例的 1 MiB 内文档；从确认打开到所有非受限公式 / 图表可见目标 5 秒内，至少 5 次记录，并验证局部错误不阻塞正文 |

### 8.3 安全与容量保护（建议默认值）

| 项目 | 边界及超限行为 |
| --- | --- |
| 单个 Markdown | 最大 10 MiB；读取前后均检查，超限拒绝并提示 |
| 单张本地图片 | 最大 20 MiB、解码尺寸最大 2500 万像素；超限显示占位，不阻塞全文 |
| 单窗口图片预算 | 累计解码内存目标上限 256 MiB，按需加载 / 回收；无法满足时显示受限提示 |
| 目录扫描 | 最多 5 万条总条目或 1 万份 Markdown，任一先到则停止并明确提示不完整 |
| 目录深度 | 最多 64 层；达到边界的分支标记跳过，其余分支继续 |
| 渲染保护 | 单次渲染超过 8 秒可中止，界面保持可操作并允许重试；技术验证时检查可取消性 |
| 公式 / 图表保护 | 单个公式源文本最大 16 KiB，单个 Mermaid 块最大 64 KiB；单块渲染 3 秒超时降级为源码。每文档最多增强渲染前 200 个公式、20 个 Mermaid 块，剩余逐项标注超限并展示源码，不静默遗漏 |

以上为首版保护边界，而非“目录只展示部分文件”的默认设计。在边界内且有访问权限的普通目录必须完成全量发现。

### 8.4 数据安全与隐私

- 默认零云端请求；用户主动打开外部链接时才交给系统浏览器。不得因 Markdown 包含 URL 就自动联网。
- 不上传文档正文、文件名、目录树和本地路径；本地日志默认不记录正文或完整敏感路径。
- 日志保留必要的操作类别、耗时和错误码；诊断导出如后续提供，需单独授权。
- 启动模式、恢复目标路径与必要阅读位置仅存于应用数据目录，受清空历史规则管理，不上传。
- P0 所有阅读流程以只读方式访问用户文件；验收应比较文件字节 / 哈希，不依赖访问时间判断是否被修改。
- 共享最近记录和设置应集中管理并可靠写入，避免多个窗口并发覆盖或产生损坏元数据。

## 9. 技术约束与实现边界

本节约束实现方向，不定义代码签名、目录脚手架或具体依赖版本。

### 9.1 应用分层

| 层 | 责任 |
| --- | --- |
| mygo / Go 原生层 | 系统对话框、窗口生命周期、本地文件访问、路径授权、目录扫描、变更监听、元数据持久化 |
| 绑定与传输层 | 类型化请求 / 响应、按窗口定向事件、错误映射、就绪握手、任务取消与过期结果过滤 |
| React 界面层 | 文件树、正文渲染、查找、局部状态反馈、侧栏布局与键盘交互 |

### 9.2 必须遵循的原则

1. 采用一个应用进程管理多个原生窗口是建议方案，不把“单进程”误解为“只能有一个窗口”。最终以锁定 mygo 版本的真实能力验证为准。
2. 每个窗口具备独立身份和阅读上下文；文件变更可以共享监听，但事件必须准确路由，不能把文件 A 内容误发给窗口 B。
3. 页面就绪前收到的打开请求不得静默丢弃。多次打开是多个独立用户意图，应有序处理；达到队列或资源边界时明确提示，不可简单只保留最后一次。
4. 目录扫描、文件读取不能阻塞原生主线程。窗口关闭后取消专属任务，快速切换通过请求标识或内容版本拒绝迟到结果。
5. React 通过统一传输适配调用 Go 能力；前端不能直接获得任意磁盘读取权限，后端不能仅凭前端提供的路径授予访问。
6. mygo 生成的 TypeScript 绑定由生成工具维护，不手工修改；API 和工具链版本以选定版本源码、生成模板为准。
7. 目录或文件更新事件需能够触发重新同步，避免页面重载、事件丢失或扫描并发造成永久过期。
8. 多窗口共享的元数据由应用层统一写入；异常恢复不能静默覆盖损坏的配置文件。
9. 生产包不依赖开发服务器，不向用户交付必须自行运行 Vite / Node 的启动流程。
10. P0 数学公式与 Mermaid 的依赖、字体、安全配置和图类型须在技术验证中锁定；局部渲染可取消、严格安全模式、输出清理和离线能力必须验证，不能仅确认普通 Markdown 渲染正常。
11. P1 起菜单点击与快捷键调用相同命令、共享启用条件及撤销 / 未保存规则；阶段未交付的快捷键不得触发浏览器默认写入、导航或开发工具动作。

### 9.3 本地经验资料

后续实现前应按任务读取仓库已有资料，不能将其中其他应用的业务参数直接当作本产品需求：

- `.claude/skills/mygo-web-app/SKILL.md`：WebView 前端、绑定、窗口集成、构建验证。
- `.claude/skills/mygo-web-app/references/desktop-integration.md`：就绪握手、原生输入、窗口与元数据持久化注意事项。
- `.claude/skills/mygo-app-scaffold/SKILL.md`：模板、工具链和初始化经验。
- `.claude/skills/mygo-desktop-app-dev/SKILL.md`：已实践的绑定、取消、布局及真实窗口验证经验。

当前未初始化应用，也未锁定或验证 mygo 版本。资料中的版本与性能记录不是本项目的验证结论，尤其不能代替原生多窗口验证。

## 10. P1 编辑与保存规划

用户已确认 P1 增加编辑和保存。以下为实现前必须展开的需求骨架，P0 不提供隐藏编辑入口或不可用的保存按钮。

### 10.1 编辑能力

- 提供明确的阅读 / 编辑状态，支持编辑当前 Markdown 源内容。
- 建议先采用源码编辑与预览切换或分栏方案；是否实现 Typora 式所见即所得编辑，需要另行确认，不能默认视为已承诺。
- 支持基本撤销 / 重做、编辑后预览同步、新建 Markdown 文档。
- 文档编辑状态按窗口区分，未保存内容不得因切换文件或读取外部更新而丢失。
- P1 通过编辑 / 段落 / 格式菜单和截图对应快捷键操作当前编辑缓冲；菜单能力不等于已承诺所见即所得，具体模式仍待确认。
- P0 已支持的公式 / Mermaid 在编辑预览中继续渲染；插入公式块、代码块属于 P1 编辑操作，不改变 P0 的阅读交付。

### 10.2 保存与退出保护

- 支持保存、另存为和明确的未保存标识；`Ctrl+S` 在 P1 才获得真实保存语义。
- 关闭窗口、切换文档、替换工作区及退出应用时，存在未保存修改必须给出保存、放弃、取消。
- 采用可靠保存流程，保存失败保留编辑缓冲并报告原因，不能先清除未保存标记。
- 保存编码建议为 UTF-8 无 BOM；已存在文件的换行和 BOM 保留策略应在 P1 详细设计中确认，禁止未经说明批量改写。
- 是否自动保存、崩溃草稿恢复及保存备份，需另行确定，不自动纳入第一批编辑交付。

### 10.3 外部及多窗口冲突

- 同一文件在多个窗口编辑时，保存前检查磁盘版本，禁止后保存窗口静默覆盖前一窗口的修改。
- 有未保存修改时发现外部变更，不得按 P0 的自动刷新逻辑覆盖编辑缓冲。
- 冲突至少提供保留当前编辑、重新载入磁盘版本、另存为等明确路径；需要覆盖磁盘时二次确认。
- 目录重命名、文件移除和权限变动时，允许通过另存为抢救未保存内容。

## 11. Agents 预留边界

### 11.1 P0 只预留空间与边界

- 右侧为独立可折叠区域，未来可以承载组件，但首版不建立 Agents 会话、服务或数据库。
- 窗口、工作区、文档在产品概念上相互区分，便于后续明确“哪个窗口的哪份内容”被授权给 Agents。
- 不为了未来 Agents 提前上传、向量化、索引或缓存整目录正文。

### 11.2 后续接入前需要重新评审

- Agents 获取的是当前文件、选中文字还是整个目录，是否逐次授权。
- Agents 会话按窗口还是按工作区隔离，关窗后是否保留。
- 云端 / 本地执行、内容发送提示、密钥存储与日志脱敏。
- 是否允许写文件、执行命令，以及人工确认、审计、撤销和冲突策略。

Agents 不是 P1 的默认交付内容，也不影响 P0 / P1 的正常阅读或编辑。

## 14. 评审建议与开放项

产品方向的关键问题已确认，以下为可调整但不阻塞本文交付的事项：

1. **P0 范围确认：** 是否接受将文内查找、最近打开和自动刷新纳入首版，以支持日常阅读闭环；如需更小版本，可以单独下调排期。
2. **窗口习惯：** 是否接受“非空白窗口打开新内容时默认创建新窗口”，而目录树点击始终在当前窗口切换。
3. **图表范围：** 公式与 Mermaid 已确定进入 P0；当前六种图表和 LaTeX 常用命令范围是否覆盖实际样本文档，更多图类型另行评估。
4. **隐私与离线：** 是否接受远程图片不加载、HTML 不执行、越界本地图片阻止的默认策略。
5. **容量基线：** 提供有代表性的目录、超长文档和图片样本后，再确认性能与大小限制。
6. **P1 编辑方式：** 源码编辑加预览，还是 Typora 式所见即所得；后者不能只按基础源码编辑器估算。
7. **菜单细节：** 截图未展开的子菜单和未显示的快捷键不作为已知事实；进入对应阶段前逐项明确，避免以“与 Typora 相同”替代验收标准。

这些开放项的存在表示仍有建议待评审，不影响 C-01 至 C-12 作为已确认约束。本文不包含任何已经实现、测试通过或完成发布的声明。

## 16. P1–P3 阶段交付与验收

### 16.1 P1：基础编辑闭环

**交付：** 第 10 节、FILE-01/05/07/08/10、EDIT-01/02/03/06/08/11/12/13/14/15/22 的 P1 部分、PARA-01/02/03/04/06/07/10/11/12/13/14/15/16/17/20、FORMAT-01/02/04/05/07/10、VIEW-06，以及第 15 节标明 P1 增加的既有能力菜单入口。

- 编辑、保存、另存为、保存全部、关闭和切换的保护形成完整闭环；新建文档不未经授权写入磁盘。
- 菜单与对应快捷键行为一致，同一编辑可撤销 / 重做；只读时不能绕过模式或焦点限制修改内容。
- 同文件不同窗口分别有修改时，冲突明确处理；“保存全部”部分失败不把全部窗口脏状态清空。
- 选择、查找替换等子菜单在开工前定义，未展示的子项快捷键不得作为已确认映射；替换范围与撤销粒度有测试。
- 延续 P0 公式 / Mermaid、本地资源安全和启动设置，不因进入编辑模式退化或丢失恢复偏好。

### 16.2 P2：效率、高级排版与输出

**交付：** 第 15 节所有标记 P2 的能力 / 入口 / 快捷键，以及阶段前明确的相关子菜单；建议加入“主题”菜单入口与更多内置主题。

- 移动、回收站删除、另开父目录及图片落盘均先处理未保存内容、权限和冲突；多窗口同步路径或失效状态，不静默永久删除。
- 表格、脚注、提示块、正文目录、下划线和注释先明确持久化语法，再同时具备插入 / 修改、阅读、保存重开能力，不以源文被破坏换取显示效果。
- 导出 HTML / PDF 和打印支持受控公式 / Mermaid、长表格与本地图片；外部资源默认仍不联网，取消 / 失败不覆盖目标文件或影响原文。
- 大纲 / 列表 / 文件树三种左侧视图切换保持当前文件；目录搜索只访问已授权范围，扫描 / 搜索可取消并提示容量限制。
- 专注、打字机、全屏、缩放、置顶及窗口切换仅作用于明确范围；测试与标题命令、文本输入及系统快捷键的冲突。
- 复制 HTML、简化格式、图片和富文本粘贴均执行内容清理；禁止借此触发文档内脚本或绕过远程图片策略。

### 16.3 P3：高级辅助与受控诊断

**交付：** 第 15 节所有标记 P3 且在阶段启动前已确认具体范围的能力；待细化项目若未冻结范围不得按父菜单名称验收。

- 导入以新文档承载，原文件不变；恶意 HTML、宏、异常格式和过大输入不得执行或阻塞界面，格式损失明确提示。
- 数学工具、代码工具、智能标点、拼写检查默认本地运行；不引入默认远程服务、自动执行代码或隐含 Agents 依赖。
- 智能替换可关闭、可撤销，不能改变代码块中不应转换的标点，不静默批量重写历史文档。
- 开发者工具仅在诊断开关允许后由显式操作打开；生产默认不开放远程调试，退出诊断状态可关闭。
- Agents、完整会话恢复、其他操作系统和独立浏览器版不因 P3 存在而被视为承诺范围。
