# Mile Typora 开发计划

> 依据：[PRD.md](PRD.md) v0.3（第 6 节 FR、第 12 节验收、第 13 节推进顺序、第 15–16 节菜单分期）、[decisions.md](decisions.md)、[DESIGN.md](../DESIGN.md)、[CLAUDE.md](../CLAUDE.md)。
> 用途：把 PRD 的 M1–M6 拆成可以依次交给 agent 开发、做完即可测试的小阶段。
> 状态：2026-11-16 创建。M1-0（脚手架）完成，M1-0b（外壳对齐设计稿）部分完成，其余未开始。每完成一个小阶段，更新第 11 节进度表。

## 1. 总则

### 1.1 编号与顺序

- 小阶段编号为 `里程碑-序号`，如 `M2-3`。同一里程碑内按序号依次开发，前一阶段验收通过后才开始下一阶段。
- 一个小阶段只交付一个可以独立测试的结果，规模控制在一个 agent 会话能完成并验证的范围内。完成不了就拆成 `M2-3a`、`M2-3b`，并在本文登记。
- 里程碑之间有门禁（1.5 节），门禁没通过不进入下一个里程碑。

### 1.2 每个小阶段的工作流

1. **确认范围**：读本文对应卡片和其中列出的 PRD 条目。卡片和 PRD 冲突时以 PRD 为准，并回来修正卡片。
2. **读 skill**：读卡片"要读的 skill"中的 `SKILL.md`，`references/` 只读命中的章节。
3. **先写测试**：按 `test-driven-development`，先写会失败的测试，再实现。
4. **对照设计稿**（界面阶段必做）：先看第 2 节 2.3 表中的本阶段行，再打开对应画板；实现时只使用设计稿里已有的元素和令牌数值。
5. **实现**：只改卡片列出的范围；需要跨范围改动时先停下说明。
6. **自动验证**：跑 1.4 节的命令，全部通过。
7. **界面对照**（界面阶段必做）：按 2.5 节截图对照、读取 2.4 节数值，结果写进汇报。
8. **原生验收**：在真实 Windows 11 窗口里按卡片"原生验收"逐条操作。工具截不到原生窗口时，请用户确认并记录结果。
9. **同步文档**：改了绑定或事件，就同步 `docs/develop/接口契约.md`；有新的取舍，就在 `decisions.md` 加条目；有新踩的坑，就记进 `docs/踩坑记录.md`。
10. **汇报**：用 1.3 节模板。
11. **提交**：用户同意后再提交，只 `git add` 本阶段的路径，提交信息遵循 Conventional Commits。

```text

```

"自动验证"和"原生验收"必须分开写。构建通过不等于原生验收通过（CLAUDE.md §8）。

### 1.4 固定的自动验证命令

```bash
go vet ./...
go test ./...
go test -race ./internal/...
bun run generate
bun run typecheck
bunx vitest run
bun run build:web
```

- 改了 Go 导出的绑定方法、参数结构体或事件后，必须跑 `bun run generate`，并用 `git diff src/mygo.ts` 确认生成结果。
- `go test -race` 在 M1-1 有了并发代码后才是必跑项。**本机暂无 C 编译器（gcc），`-race` 跑不了**；M1-1 起用并发测试配合人工审查，装好 MinGW 后补跑（decisions.md D-T14）。
- 涉及渲染安全的阶段，另跑 `go test -run=^$ -fuzz=<目标> -fuzztime=60s ./internal/markdown/`。
- 原生运行用 `bun run dev`，打包用 `bun run build`。
- 界面阶段另跑浏览器面板核对：`.claude/launch.json` 的 `web-shell`（端口 5274）打开前端外壳，按第 2 节读取计算样式并截图。浏览器里没有 mygo 运行时，状态栏显示"连接失败"属预期，只看布局与主题。

## 2. 界面规格（严格按设计稿）

界面不是"看着差不多就行"。设计稿 `docs/design/mile-typora-design.html` 是视觉唯一基准，本文这一节把它的要求落到每个阶段。

### 2.1 三个文件的关系与优先级

| 文件 | 角色 | 冲突时 |
| --- | --- | --- |
| `docs/design/mile-typora-design.html` | 视觉基准：布局、尺寸、组件形态、状态 | 以它的数值为准 |
| `DESIGN.md` | 文字契约：令牌表、组件规则、反模式 | 与设计稿不符时立刻改 DESIGN.md |
| `src/styles/tokens.css` | 落地值，来自设计稿的 `:root` 与深色块 | 与设计稿不符时立刻改它 |

改界面的顺序固定：**先读对应画板 → 需要时改 DESIGN.md → 改 `tokens.css` → 改组件 → 截图对照**。跳过任何一步都算未完成。

| 左栏宽 / 右栏宽 | 240px / 260px | `--sidebar-left-w` `--sidebar-right-w` |

| 文件树行高 / 层级缩进 | 28px / 16px | `--tree-row-h` `--tree-indent` |
| 图标尺寸 | 16px 行内 / 20px 工具栏 | `--icon-sm` `--icon-md` |
| 圆角 | 输入与按钮 4，卡片与提示条 6，浮层与对话框 8 | `--r-sm` `--r-md` `--r-lg` |

另外三条硬约束，每次都用脚本断言：

1. 整窗不出现纵向滚动条（`document.documentElement.scrollHeight <= innerHeight`）；
2. 组件样式里没有 hex / rgb / hsl 色值，也没有令牌之外的字号、圆角、阴影；
3. 浅色与深色两套都截图，两套的对比度都符合 DESIGN.md §2.6。

### 2.5 验收方式

1. **对照画板**：把当前界面与本阶段对应的画板并排看，逐项列差异；差异要么改界面，要么先在 DESIGN.md 里说明理由并经用户同意。
2. **数值读取**：按 §2.4 读取计算样式，结果写进汇报。
3. **两套主题**：浅色、深色各截一张；外观相关阶段再测 1000 宽与跟随系统。
4. **原生窗口复核**：浏览器面板只能看布局；字体渲染、DPI、原生标题栏、任务栏图标必须在真实窗口确认，由用户确认后记录。

### 2.6 禁止清单

- 设计稿里没有的元素不新增：不加图标墙、插图、宣传语、"即将上线"、占位假数据。
- 右栏只放标题与折叠按钮，不放聊天框、模型选择、输入框。
- 不用 emoji 当图标；图标只用 `lucide-react`，线宽 1.75。
- 页面元素不加阴影；浮层只用 `--shadow-1` / `--shadow-2`；不叠加边框与阴影。
- 不用渐变、不用彩色卡片、不用强调色表达状态（强调色全应用只有一处用途）。
- 未接通的按钮不显示，或显示为停用态并设 `aria-disabled`；不出现点了没反应的按钮。
- 动效只动 `opacity` / `transform`，时长取 `--dur-*`，`prefers-reduced-motion` 下为 0。
- 应用图标不手改 PNG，只改设计原图后重跑 `scripts/make-icons.py`。


## 3. M1 技术验证

目标：用最小实现证明 PRD 13.1 的技术风险可控。完成标准：原生多窗口互不干扰；公式与六种图表离线正常；恶意内容不能绕过安全限制；能打出可运行的包。

### M1-0 脚手架（已完成 2026-11-16）

- **目标**：mygo v0.9.0 web 模板 + React 19 跑通，三栏外壳与一个最小绑定可用。
- **结果**：
  - Go 模块 `github.com/lhmile489-design/mile-typora`
  - identifier `dev.mile.typora`，开发端口 5273
  - `WindowService.Ready` 绑定可调用

- **未覆盖**：工具栏只有侧栏开关，其他入口要等对应阶段接通后才出现（PRD 7.3、CLAUDE.md §9）。

### M1-0b 外壳对齐设计稿（画板 2）

- **前置**：M1-0。
- **PRD 范围**：§5 信息架构与布局、DESIGN.md §4、§8.1、§8.8–§8.11、§8.14。
- **主要文件**：`src/app/App.tsx`、`src/styles/app.css`、`src/styles/tokens.css`（补差）、`public/theme-init.js`。
- **要读的 skill**：`design-tokens`（令牌落地与对比度）、`frontend-design`（只在设计稿没覆盖的细节上参考，不得改变设计稿的数值）。
- **本阶段要做**（逐条对照画板 2）：
  1. 工具栏：分组［打开文件、打开目录、新窗口］｜［刷新、查找］｜弹性空白｜［左栏、右栏、设置］，组间 1px×20 竖线；"打开文件""打开目录"带文字，其余纯图标且都有 `aria-label`；未接通的按钮按 §8.1 显示停用态。
  2. 左栏：空状态文字"尚未打开文件或目录"，居中，`--text-muted`。

- **自动测试**：
  - 组件渲染测试：三栏、工具栏分组、`aria-pressed`、`aria-label` 齐全
  - 快照式断言：`tokens.css` 的令牌名与值等于设计稿提取结果
  - 脚本断言 §2.4 的尺寸与"无整窗滚动"
- **原生验收**：真实窗口里核对工具栏 44、状态栏 26、左右栏 240/260、字体渲染、深浅两套、缩放 100%/150%。

### M1-1 窗口注册表与多窗口

- **目标**：一个进程开多个原生窗口，每个窗口有独立上下文，关窗释放，最后一窗关闭即退出。
- **前置**：M1-0。
- **PRD 范围**：FR-02（第 1、6、7、8 条）、§9.2 第 1–2 条、AC-03、AC-04。
- **主要文件**：`internal/winctx/`（注册表，以 `win.ID()` 为键，每窗口 ctx）、`internal/service/window.go`（`NewWindow`、`Close`）、`main.go`、`src/app/` 工具栏"新建窗口"按钮、`Ctrl+Shift+N`。
- **要读的 skill**：`mygo-web-app`（`references/desktop-integration.md` 窗口注册表）、`go-service-engineering`（ctx 与分包）。
- **自动测试**：
  - 注册表增删、并发访问（`-race`）
  - 关窗后 ctx 被取消

### M1-2 打开请求队列与就绪握手

- **目标**：页面就绪前到达的打开请求不丢、按序投递；单实例转交第二次启动的参数。
- **前置**：M1-1。
- **PRD 范围**：§9.2 第 3 条、FR-02 第 8 条、AC-20（意图不静默丢失部分）。
- **主要文件**：`internal/winctx/intents.go`（每窗口有界队列，容量 32）、`WindowService.Pending` / `Ack`、`main.go` 的 `OnSecondInstance` 与 `open-request` 事件。
- **要读的 skill**：`mygo-web-app`（就绪握手、单实例、事件路由）。
- **投递模型**（实现时按原生实测修正）：**队列是唯一真相，事件只是提示，页面用 `Ack` 确认**。
  - 请求留在 Go 侧队列里，直到页面 `Ack(seq)`；未确认的请求每次 `Pending(after)` 都会重新返回
  - 页面就绪后新来的请求，除入队外再发一次 `open-request` 事件，页面按 `seq` 去重
  - 这样无论握手响应被丢弃（如 React StrictMode 首次挂载）还是事件丢失，都不会丢请求
- **自动测试**：
  - 入队顺序与出队顺序一致
  - 队列满时返回 `queue_full`，不丢弃已有请求；`Ack` 后释放容量
  - 未确认时重复 `Pending` 返回同一批请求，`Ack` 后不再返回
  - 事件发送失败时请求仍留在队列里
  - `Seq` 并发下不重复、递增
- **原生验收**：
  1. 应用运行中，命令行再启动一次带参数的实例，第一个实例收到参数（先在状态栏显示），第二个进程退出；
  2. 连续快速触发 5 次"新建窗口"，得到 5 个窗口，没有遗漏。
- **完成标准**：自动测试通过，原生两条通过。
